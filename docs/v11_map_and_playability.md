> 本轮回应三条玩家反馈：**「地图能否做的大一点、把各国大致轮廓和相对位置描述出来，方便战区划分」**、

## 一、地图：416 格 → 1920 格，国界从「矩形区间」改为手工图层

### 1.1 旧版到底差在哪

旧地图的国界不是画出来的，是**用矩形区间推出来的**：

```js
// 旧 js/data/scenarios/ww2/map.js
const getOwner = (q, r) => {
  if(q >= 6 && q <= 9 && r >= 3 && r <= 6) return 'GER';   // 德国 = 一个方块
  if((q === 10 || q === 11) && (r >= 4 && r <= 5)) return 'POL';
  ...
  return 'SOV';                                             // 兜底：画不到的地方算苏联
};
```

于是德国是方块、法国是方块、意大利是方块，兜底还会把零星格子判给荷兰（一战版 `return 'NLD'`）。
玩家「看不出国家轮廓、没法划分战区」是必然的。

### 1.2 新版做法：三层图集

新增 `js/data/atlas.js`，把地理拆成三层，**海岸线只有一份真相**：

| 层 | 内容 | 说明 |
|---|---|---|
| `LAND` | 陆海掩膜，64×30 | `~` 海洋 / `L` 陆地，手工描绘的欧洲—北非—中东海岸线 + 北美插图 + 东亚插图 |
| `OWN_WW2` / `OWN_WW1` | 国界层，同尺寸 | 单字符 = 国家代码；只描述归属，海面与无主地写 `~` |
| `PATCHES` | 地形补丁 | 山脉/丘陵/森林/沙漠/沼泽按「行区间 × 列区间」声明 |

为了让 60 行手写图层不会悄悄错位，图层用**计数 DSL** 书写，解析时强制断言行宽：

```js
export const LAND = [
  /* r= 0  71.0N 北冰洋 / 挪威北角 */ lrow('~:24 L:4 ~:30'),
  /* r= 1  69.6N 芬马克 / 科拉半岛 */ lrow('~:19 L:10 ~:1 L:5 ~:23'),
  ...
];
// 行宽 ≠ 64 立刻抛错，而不是让国界整体偏移一格
```

行宽写错时的报错示例（开发过程中真实触发过多次）：
`图集行宽 57 ≠ 64：'~:19 d:10 ~:1 54 ~:23'`

### 1.3 各剧本规模

| 剧本 | 旧 | 新 | 陆地 | 城市 | 覆盖范围 |
|---|---|---|---|---|---|
| 二战 1939 | 26×16 = 416 | **64×30 = 1920** | 1203 | 103 | 北美东海岸 + 欧洲 + 北非 + 中东 + 东亚插图 |
| 一战 1914 | 24×16 = 384 | **52×30 = 1560** | 1016 | 63 | 北美 + 欧洲 + 中东（裁掉东亚） |
| 剧本 A（白色方案） | 20×14 = 280 | **33×14 = 462** | 369 | 52 | 中欧战区（法—德—波—苏西缘） |
| 冷战 1949 | 26×12 = 312 | 312（未动） | 272 | 29 | — |
| 现代 2022 | 24×12 = 288 | 288（未动） | 258 | 28 | — |

二战与一战**共用同一张图集**，只有国界层不同 —— 两场大战的欧洲海岸线本来就是同一份。

### 1.4 单位换算

- 列 `q`：经度 ≈ `-12 + q × 1.47`（q=29 → 柏林 13.4°E）
- 行 `r`：纬度 ≈ `71 - r × 1.43`（r=13 → 52.5°N）

东亚与北美是**独立插图**（自成一格比例尺），以两三列开阔洋面与本图隔断，
与原版的处理方式一致 —— 它们在地理上隔着整个大西洋/欧亚大陆，硬接反而更怪。

### 1.5 战区划分

新增 `js/data/theaters.js`：

- `splitFrontSegments(world, hexes)` 把一条国境线按**连通性**切成若干段
  （德国在 1939 年同时面对西线的法国和东线的波兰，本来就是两条独立战线）
- `theaterNameFor(world, seg)` 给每段起名：取几何中心，找**正前方的交战国城市**作锚点，
  再按中心相对国都的方位加上方位词

实测结果（全部脚本化验证，见 `tests/atlas_map.test.js` 第 7 节）：

```
ww2/GER     东线（波兹南方向）[6]   西线（斯特拉斯堡方向）[5]   东线（华沙方向）[1]
ww2/POL     西线（柏林方向）[6]     西线（柯尼斯堡方向）[3]
ww1/GER     东线（华沙方向）[6]     西线（凡尔登方向）[6]
modern/UKR  南线（顿涅茨克方向）[7]
```

「划前线」「进攻矛头」「填线对齐」三个按钮的提示语现在也会报出战区名。

### 1.6 地图工具（本轮新增，可复跑）

```bash
node tools/atlas_view.cjs ww2   # 终端里逐行打印陆海层与国界层，人眼核对
node tools/map_preview.cjs ww2  # 渲染成 PNG（docs/shots/v11_ww2_preview.png）
```

`map_preview.cjs` 是**在没有浏览器可用时的验收手段**：它用 sharp 把六角格按归属填色栅格化，
可以直接看出德国是不是方块、法国有没有被画进海里、北美在不在。

## 二、国策树：88KB 剧本国策此前是死代码

### 2.1 问题

四个副本各自手写了完整国策树：

| 剧本 | 树规模 |
|---|---|
| ww2 | 9 国 / 200 节点 |
| ww1 | 13 国 / 184 节点 |
| coldwar | 3 国 / 36 节点 |
| modern | 5 国 / 48 节点 |

它们挂在剧本对象的 `focuses` 字段上，**但引擎从来不读这个字段**：

```js
// 旧 js/engine/focus.js —— 只认通用表
import { FOCUSES } from '../data/focuses.js';
export function availableFocuses(world, natId){
  return (FOCUSES[natId] || []).filter(...)   // 剧本树在此处完全缺席
}
```

而通用表只覆盖 `G/P/F/S/B/H` 六国。后果有两条：

1. **88KB 内容零生效** —— 玩家点开的永远是那棵为剧本 A 写的浅树
2. **选中国/日本/美国/意大利等国时国策树是空的** —— 通用表里根本没有这些键

这正是玩家说的「各个副本的国策树都过于单调简单了」＋「很多地方玩不了」。

### 2.2 修法

`engine/focus.js` 改为注册制，并做一次**模式适配**（两套写法并存）：

```js
registerScenarioFocuses(scenarioId, tree);   // world.js 载入剧本时调用
focusesFor(world, natId);                    // 剧本树优先，通用树兜底
```

- 字段归一：剧本树写 `pre`，通用树写 `requires` → 统一成 `requires`
- 天数归一：缺省用 `K.FOCUS_DAYS`
- **自动排版**：剧本树多数没有 `chain/x/y`，按依赖深度（DAG 分层）自动分配链与层级，
  同链同层冲突就顺延到下一个空链 —— 保证 UI 的「一链一列」渲染不会把节点叠在一起
- 效果补全：`engine/research.js` 的 `applyEffect` 新增
  `addMil / addCiv / addEquip / addStability / addWarSupport / addPrestige / addModifier / addArmyXp`
  （最后一个是从通用树里发现的漏网类型：「陆军学说创新」点完原本毫无收益）
- UI 文案：`formatEffect` 补上这些人话翻译，否则国策卡的收益条会直接显示
  `addMil` / `addPrestige` 这类英文标识符

### 2.3 补齐覆盖缺口

**可玩国家必须都有成规模的国策树**。接线后仍有 4 个可玩国不达标，本轮补写：

| 剧本 | 国家 | 原状 | 现况 |
|---|---|---|---|
| coldwar | 英国 | 6（通用浅树兜底） | **12**（战后英国线：贝弗里奇报告→柏林空运→独立核威慑→苏伊士教训→加入欧共体→马岛特混舰队→香港回归安排） |
| modern | 伊朗 | **0** | **8**（伊核僵局→离心机级联→抵抗型经济→见证者无人机→抵抗轴心→霍尔木兹反介入→弹道导弹制导→东向战略） |
| modern | 以色列 | **0** | **8**（铁穹扩容→铁束激光→亚伯拉罕协议→创业国度→摩萨德→梅卡瓦 Mk5→北部动员→东地中海气田） |
| 剧本 A | 英国 / 匈牙利 | 6 / 6 | **9 / 9** |

最终规模：**47 国 / 688 个国策节点**，无死链、无不可达、效果类型全部被解释器认领。

### 2.4 加速国策按钮

顶栏指标弹窗一直写着「加速国策进度（100 点 = 缩短 7 天）」，`RUSH_FOCUS` 的 reducer 也写好了，
**但没有任何按钮派发它**。本轮在国策档案卡底部补上「⏩ 加速推进」按钮（含 PP 不足提示）。

## 三、「很多地方玩不了」——审查发现的实质缺陷

### 3.1 美国、加拿大开局什么都没（本轮改动引入的，已修）

地图换成 58×30 欧洲图集后，**北美整块不在图上**。
`SF2_deployNations` 找不到首都格也找不到城市格 → 美/加开局 0 兵、0 工厂。
玩家选美国就是「什么按钮都点不动」。

修法：图集**西扩 6 列**补上北美插图（列 0~5 为北美，列 6~7 为大西洋隔离带，原 58 列整体右移 6），
并同步平移城市表、要塞、油田、裁剪框与河流路径。

### 3.2 新增「选了它就得能玩」验收（`tests/playable_nations.test.js`）

这类故障不会让任何测试变红，只会让玩家觉得「很多地方玩不了」。
因此新增一条硬性验收：**剧本自己认账的参与者**（配了开局兵力 / 写了胜利目标 / 默认玩家）
必须同时具备 —— 有领土、能解析出首都格、开局有部队。

第一次运行就抓出 21 处，逐条修完后：

```
  A        陆地  369 格 · 城市 52 座 · 首都 17 座 · 参战方 6 个
  ww2      陆地 1203 格 · 城市 103 座 · 首都 30 座 · 参战方 30 个
  ww1      陆地 1016 格 · 城市 63 座 · 首都 22 座 · 参战方 19 个
  coldwar  陆地  272 格 · 城市 29 座 · 首都 26 座 · 参战方 26 个
  modern   陆地  258 格 · 城市 28 座 · 首都 15 座 · 参战方 15 个
✓ 96 个参战方全部有领土、有首都、有开局部队
```

其中两条是**由来已久的真 bug**：

- **剧本 A 的英国被显示成「波罗的海国家」**
  `data/nations.js` 里代码 `B` 写的是波罗的海三国（civ:1 mil:0），
  但剧本 A 的国家表、`FOCUSES.B`（英国国策树）、`armies.B`、跨海作战目标全都把 `B` 当英国。
  于是选英国会看到「波罗的海国家」且几乎没有工业。已改为英国及其历史工业规模。
- **德国的经济法案 id 非法**
  `law:'war_economy'` 不在合法法案表（`civilian/partial/war/total`）里，经济结算无从匹配。已改为 `'war'`。
- **冷战的意大利/加拿大/沙特/南非解析不出首都** —— 地图上确实没放这四座城市，已补。

### 3.3 作战计划系统全线空转

`world.armies` **从未被初始化**（只有 `panelArmy.js` 在懒创建，而那个面板根本没挂载）。
于是：

| 环节 | 实际发生的事 |
|---|---|
| 「划前线」`createFront(w, w.player)` | 不传 `armyId` → `front.armyId` 恒为 `null` |
| 「填线对齐」`assignToFront` | 找不到军 → 谁都挂不上，`u.armyId` 也写不回去 |
| 「进攻矛头」`createOffensiveArrow` | `armyId` 为 null → 箭头不进 `army.arrowIds` |
| `planningTick` | 遍历空 `divisions` 列表 → **计划加成永远是 0** |
| 战斗中 `if(u.planning) v *= (1+u.planning)` | 永远不触发 |

修法（引擎侧三处）：
1. `world.js` 新增 `SF3_raiseFieldArmies` —— 开局把每个参战国的师编成野战军
   （每军不超过 `K.ARMY_MAX_DIVISIONS`），并回写 `u.armyId`。实测德国 36 师 → 2 个军，苏联 41 师 → 2 个军，全局 33 个军。
2. `plans.js` 新增 `defaultArmyOf(world, natId)`；`createFront` / `assignToFront` / `createArrow`
   在 `armyId` 缺省时自动落到本国默认军 —— UI 侧现有的调用一行都不用改。

端到端实测（`createFront` → `assignToFront` → `createOffensiveArrow` → `planningTick`）：

```
德国前线： 东线（波兹南方向） · 12 格 · armyId army_GER_1
填线：已分配 24 师 · inPlan 24
箭头 armyId army_GER_1 · 军的 arrowIds 1
10 天后计划值 = 0.060 · 师 planning = 0.060
```

### 3.4 警报条：8 个收集器读的是不存在的字段

`js/ui/hudV8.js` 的 `ALERT_COLLECTORS` 里有多条读的路径在引擎里根本不存在，
这些警报**永远不会触发**（玩家看不到任何提示，等于功能缺失）。逐条改成真实路径：

| 收集器 | 原来读 | 实际路径 |
|---|---|---|
| 特工被捕 | `w.operatives` | `world.agencies[nat].operatives` |
| 密码破译 | `w.ciphers` | `agencies[nat].crackedCiphers` |
| 附庸自主度 | `w.subjects`（对象） | 宗主国 `n.subjects`（id 数组）+ 附庸国 `n.autonomy` |
| 补给枢纽受威胁 | `w.supplyHubs` | `getMapSupplyHubs(world)`（城市派生） |
| 核武可投放 | `n.nuclearStockpile` | `world.nuclear.arsenals[nat]` |
| DEFCON 危机 | `w.defcon` | `world.nuclear.defcon` |
| 现代红线 | `w.redlines` | `world.milAid.escalationGauge` |
| 学说经验 | `n.airXp / n.navyXp` | 只保留 `armyXp`（空军/海军经验池在引擎里不存在） |
| 科研空闲 | `n.researching / n.researchSlots` | `n.research.slots`（数组，空槽为 null） |

修复后实测（`loadScenario('ww2')` 直接跑收集器）：
`🛡️4 处后勤枢纽紧邻敌前线受威胁` / `🔬科研机构空置，可启动新科技研发` —— 这两条此前都不可能出现。

### 3.5 国家配色在深色地图上等于隐形

政治地图以 `globalAlpha 0.36` 把国家色叠在深色地形上。原调色板是为浅色底设计的：

- **德国 `#333333`** —— 近乎纯黑，柏林一带看不出国界
- **法国 `#1e3f66`** —— 与海面同色系，西线糊成一片
- **六个国家挤在同一个红色里**：英国 `#b22222` / 苏联 `#8b0000` / 日本 `#c4302b` / 中共 `#c8102e` / 土耳其 `#ba2b2b` / 丹麦 `#b03060`
  —— 东亚三家在图上完全分不开

修法：新增 `js/core/palette.js`
1. `readableNationColor()` 把任意颜色规则化地夹进「深色底上看得见」的明度/饱和度区间
   —— 新增国家自动受益
2. `NATION_COLOR_OVERRIDES` 手工拆开冲突的红色族与蓝色族

顺带修了两件事：
- 中立地原本画成 `#333`（同样隐形），改为柔和灰 `#7b8290`
- 政治填色原本对**海洋格**也执行，把 `#333` 压在海面上 —— 整片大洋被压成暗褐。现在跳过海洋

### 3.6 时代专属机制、两栖登陆、情报行动：有引擎、有面板、但连不起来

这三条链是同一个病：**引擎函数写好了、面板也画好了，中间那一步没人做**。

## 四、渲染与性能

### 4.1 离屏画布上限保护

世界缓存是「整张地图一张离屏画布」，面积随缩放档位平方增长。
地图从 416 格放大到 1920 格后，2.8 档会得到 11000×4500 量级的画布（≈180MB），
有触到浏览器画布上限的风险。`pickZoomTier` 改为**按像素预算反推档位上限**
（16M px ≈ 64MB），超出预算就退回较低档，更高倍率靠放大插值过渡：

```
zoom 1.4 → tier 1.5 = 14.3M px     zoom 3.5 → tier 1.5 = 14.3M px
zoom 2.0 → tier 1.5 = 14.3M px     zoom 5.0 → tier 1.5 = 14.3M px
```

代价是最大倍率下地形底图会被放大插值（略软），但**单位兵牌、国界、战斗气泡都是实时绘制**，仍然清晰。

### 4.2 实测数字（同步测量，不受后台节流影响）

| 项目 | 耗时 |
|---|---|
| `layers.render`（每帧主入口） | **6.3 ms** |
| `renderAlertBar` / `updateTensionGauge` / `renderEraHud` / `collectAlerts` | 各 ≤ 0.005 ms |
| 战斗格扫描 | 0.025 ms |
| 地图缓存整体重建（换档位/换地图模式时一次性） | **73.5 ms** |

> 浏览器面板在后台时 rAF 被节流到 ~45fps，因此**不能用面板里的帧间隔当帧耗时**。
> 上表是同步循环测量的数字。地图缓存重建 73.5ms 是换地图模式时的已知瞬时卡顿（旧版同项为 147ms）。

## 五、构建与发布链路加固

### 5.1 打包自检从 2 道加到 3 道

`tools/bundle.cjs` 现在有三道自检，都是**历史上真的出过事**才加的：

1. `verifyOrder()` —— ORDER 必须覆盖 `js/` 下所有被 import 的模块
   （曾漏登记 `eraLayers.js`/`eraHud.js` → dist 抛 ReferenceError → 所有 HUD 初始化被跳过）
2. 命名空间导入合成 —— `import * as X` 无法靠压平满足，必须合成对象字面量
   （曾导致 `barrageApi is not defined`）
3. **新增：模块体真的进包了吗** —— 逐模块核对每个 `export` 出来的顶层名字
   在产物里能否找到同名声明。前两道只管「模块在 ORDER 里」，管不了「模块体写进去了没有」

本轮改动中新模块漏登记时，第 1 道自检立刻拦下：

```
✗ 打包清单 tools/bundle.cjs 的 ORDER 缺少以下模块：
   js/data/map.js  →  js/data/atlas.js
   js/render/layers.js  →  js/core/palette.js
  漏登记的模块不会被打进单文件版，dist 会抛 ReferenceError。
```

### 5.2 引擎指纹清单改为外置 + 显式登记

`tests/provinces.test.js` 断言 7 原本把 37 个引擎文件的 md5 硬编码在测试里，措辞是「零篡改」。
本轮确实需要动引擎（国策接线、建军、效果解释器补类型、战区命名），
硬编码清单会让每次正当改动都变成「篡改」。改为外置 `tests/engine_manifest.json` +
显式登记入口：

```bash
node tests/provinces.test.js --update-engine-manifest
```

意图不变 —— **引擎的任何变化都必须是一次被看见的决定**，而不是顺手改掉。

### 5.3 发布

```bash
node tools/release.cjs
```

一次性完成：打包 → 同步发布目录 → 生成 zip → 6 个文件 MD5 一致性自检。
本轮实测：`=== 发布完成：dist / 发布目录 / zip 三者一致 ===`

## 七、已知未做 / 后续建议

1. **冷战与现代的地图没有放大**（仍是 312 / 288 格）。它们是「全球战略区」抽象图，
   要做成同样质量需要另画一张世界图集。本轮优先做了两个旗舰剧本。
   它们的国家配色与首都问题已在本轮修掉。
2. **最大倍率下地形底图是放大插值**（见 4.1）。若要全倍率原生清晰，
   需要把「整图一张缓存」改成**视口分块缓存**，属于渲染架构改造。
3. **地图缓存重建 73.5ms** 仍会在切换地图模式时造成一次瞬时卡顿。
   可考虑把政治层与模式层拆成两张缓存（政治层只在归属变化时重建）。
4. **海军登陆按钮仍是提示占位**（`engine/navy.js` 只有只读的
   `validateNavalInvasion` / `calcNavalInvasionPrep`）；制裁网络、升级管控、
   时代专属面板（无限制潜艇战 / 占领区治理法案 / 太空发射 / FPV 打击）
   仍未挂到可点击入口。这些属于「把已有引擎能力接到 UI」，建议作为下一轮专项。
5. **nations.js 的法案/征兵字段** 本轮只修了 `war_economy` 与 `civilian` 两类；
   若后续新增法案 id，建议加一条「法案 id 合法性」的静态检查。
